## 2 降水字段及独立勘误

### 2.1 发现的冲突与采用口径

冻结 DATA_DICTIONARY.csv 的 precipitation_mm 和 rain_mm 单位为 mm/hour。来源 rainfall_data_dictionary.csv 第14–15行对完整背景表使用 mm（rain字段说明较粗略）；rainfall_request_manifest.csv 的7批URL均指定 precipitation_unit=mm、timezone=Asia/Kuching、models=ecmwf_ifs，并同时请求 precipitation 与 rain。

2026-10-06读取的[Open-Meteo Historical Weather API 官方文档](https://open-meteo.com/en/docs/historical-weather-api)中 Hourly Parameter Definition 说明：这两个字段都是标记时刻之前一小时的累计量，单位为mm。precipitation代表总降水，rain代表液态降水。该页面只补充当前官方定义，不证明当年的完整响应头、请求执行、上游模型确切运行版本或现场准确性。

**独立勘误 ERR-BG-01：**后续本文字段摘要应将两字段解释为“小时累计量，单位mm，累计区间1小时，标记时刻为区间结束端点”。本批仅形成此勘误，不改冻结字典、数据、清单或版本ID。不做数值换算，不将其解释为整点瞬时雨强。

**字段选择记录 ERR-BG-02：**5.3主变量保持 precipitation_mm。rain_mm 独立保留，不互换。29,376个节点小时中，两列在10,019行不相等。官方产品定义支持变量类别不同；本批没有原响应和天气成分证据来解释每条差值，不将其一律归因于雪、阵雨或任何单一成分。

数据精度检查确认冻结 precipitation_mm 为0.1 mm精度；将来分组应保留交接第10节的整数十分之一毫米比较规则，不能先把节点平均值舍入后分箱。当前没有计算降水组速度或任何关系指标。

## 4 记录时间字段：解析事实与代码角色分开

| 诊断时差 | 范围（秒） | 中位数（秒） | 解释 |

### 4.3 9条晚到锚点诊断

定义仅为：某记录若作为自身归一化槽+15分钟决策的最新锚点，capture晚于该决策。发现9条，均来自12月31日，分布在21:30槽5条和22:00槽4条。capture−槽为910–962秒，即晚于对应决策10–62秒。所有9条均回指来源日CSV且时间值一致。

例如N005：槽21:30，拟定决策21:45，capture为21:45:42；在21:45决策不能作为最新已记录输入。另一决策中是否可作更旧输入，仍由那次实际τ及精确滞后槽决定。

不删除冻结记录，不把这9条认定为坏速度观测；只在对应决策的输入资格中按既有规则排除。9条是记录数，不是已计算的完整基准排除样本数：一条记录可能用于不同步长或多个历史位置，其他缺项也影响资格。

## 5 本批时间准入结论与边界

**结论：部分成立。**现有CSV及构建映射支持实施字面记录时间过滤，局部保存代码支持capture的应用记录角色；9条超过一个槽的记录可以由已确认规则识别。满足记录过滤的行可支持限定的回顾性代理。

仍未证明的是历史部署代码版本、完整字段导出联结、真实请求/接收/提交和时钟同步。不能据此核实真正在线到达，不能宣称15分钟是实测安全延迟，也不能由90,920条记录在自身槽+15分钟前记载推断它们都是完整合格预测样本。

E03只完成字段计算与部分来源语义子项，未整体关闭。首批验收时需决定是否接受上述已确认回顾性代理的具体证据边界，再另行授权E07样本资格工作；若要求证明真实在线到达，应先补相应证据或重新决定协议。本批没有执行后续实验。E04/E05及回顾性E06不因真实在线证据缺失而必须全部停止。
